# Code Review 第一輪（2026-09-11）

對照規格 `ESP32出廠設定工具_規格_1.md` v1.2。整體架構乾淨（config / firmware / ledger / models / numbering / provisioning / ui 分層清楚），2 個測試通過。但有兩個會讓實機必定出錯的 P0 協定 bug，以及多處規格未實作。

## P0 — 實機必掛的問題

### 1. raw REPL 協定讀取錯位（`provisioning.py` `execute()`）

MicroPython raw REPL 的回應格式是 `OK<stdout>\x04<stderr>\x04>`（兩個 `\x04`）。`execute()` 只讀到**第一個** `\x04` 就停，造成兩個後果：

- 板上發生例外時，Traceback 在第一個 `\x04` 之後，永遠讀不到 → `if b"Traceback" in output` 形同虛設，板上錯誤被靜默吞掉。
- 殘留的 `<stderr>\x04>` 留在 serial buffer 裡，**下一次 `execute()` 一開始就撞到上一輪的 `\x04` 提早返回**，之後每個指令的回應都錯位一輪。

修法：每次 execute 依序讀 `OK`、stdout 到 `\x04`、stderr 到 `\x04`、再吃掉 `>`，stderr 非空即報錯。

### 2. `machine.reset()` 後 execute 等 `\x04` 必逾時

`reset()` 走 `execute()`，但板子收到指令就重開機，永遠不會回傳結尾的 `\x04`，`_read_until` 2 秒後丟出「序列埠逾時」→ **步驟 8 每片板子都會 FAIL**（而且此時帳本已寫入）。reset 應該只送指令不等回應，或用 DTR 硬 reset。

## P1 — 規格核心功能缺失

### 3. 驗收條件幾乎沒做（規格第 6 節）

`_wait_for_boot` 只檢查 `ESP Wi-Fi OK` 和 `Traceback`。規格要求的 `Get token: <uuid>` 比對、`My MAC Address: <mac>` 比對完全沒做；RSSI、程式版本、MQTT 狀態也沒解析，帳本欄位永遠是空的。更糟的是 UI 直接顯示「✓ token 一致 ✓ MAC 一致」——這兩項根本沒驗過，是假的綠勾。

### 4. FAIL 永遠不會寫回帳本（`ui.py` `_on_failed`）

步驟 7 寫入時結果是 `WAIT`，`_on_failed` 只更新畫面、不呼叫 `ledger.update_result(mac, "FAIL")`。失敗的板子在 CSV/xlsx 裡永遠停在 WAIT，統計也數不到。

### 5. `update_result` 更新到最舊的一列（`ledger.py`）

CSV 每次重燒都 append 新列，但 `update_result` 用 `next()` 找**第一筆**符合的 MAC——重燒過的板子按「完成」時，PASS 寫到舊列，最新那列停在 WAIT。應該找最後一筆。

### 6. 編號管理有三個洞（`ui.py`）

- 使用者在畫面上改了「起始編號」後，`self.next_card` 不會更新（只在 `__init__` 設一次）→ 改了也沒用，繼續用舊號。
- config 存的是原始起始編號，不是下一個號 → **當天重開程式會重複配號**，且沒有依規格在啟動時檢查帳本內小卡編號/MAC/token 重複。
- `Ledger.backup()` 寫好了但從未被呼叫（規格第 4 節要求開工先備份帳本）。

### 7. `find_by_mac` 只查 CSV、不查 xlsx（`ledger.py`）

規格說帳本沿用既有 xlsx 的三欄舊資料。既有板子若只存在 xlsx（歷史資料），比對不到 → 會被當新板重新配號配 token，違反「重燒沿用原編號」的核心規則。

### 8. 四格並行時 Ledger 完全沒有鎖

`cards_lock` 只保護配號。四個 worker thread 同時 `append_csv`（同檔 append 交錯）、同時 `load_workbook`/`save`（讀改寫競態，可能互相蓋掉或壞檔）。Ledger 的所有寫入需要一把鎖。

## P2 — 規格偏差

- **連線無重試、REPL 失敗不會自動重燒**：規格步驟 1 要 DTR reset 重試 3 次；步驟 2 說 REPL 無回應要 erase+write flash，現在直接丟錯。另外重燒完規格要求「回到步驟 1」自動續跑，現在是丟錯要求人員重按開始。
- **韌體只比版本、不比日期**：檔名日期解析了（`firmware.py`）但從未比對。
- **wifi.dat / token.dat 沒做 sha256 驗證**：規格步驟 6 是「每個檔案」。
- **COM port 可重複選**：規格要求四格 port 不可重複，UI 沒擋。
- **「識別」按鈕沒接任何動作**：閃 TX 燈功能未實作，按了沒反應。
- **PyInstaller 打包後 esptool 會壞**：凍結後 `sys.executable` 是 `provision.exe` 自己，`provision.exe -m esptool` 不會跑 esptool。打包前要改用 esptool 的 Python API 或偵測 frozen。
- **raw-paste 模式未實作**：規格 10 說優先用（有流控、較快），目前只有一般 raw 模式。
- `append_csv` 若 CSV 被 Excel 開著會丟 PermissionError 且沒接住，整片直接 FAIL。

## P3 — 小問題

- 「今日紀錄」讀的是整個 CSV，不是今天的。
- 人工確認期間沒有背景繼續讀 log 抓 `MainStatus: STANDBY_MQTT`（規格第 6 節）。
- UI 從 step 訊息字串反解析 MAC / 卡號很脆弱——`_on_finished` 其實拿得到完整 `record`，直接用它就好。
- `config.ini` 明碼存 WiFi 密碼——README 有揭露，符合「不寫入 CSV/xlsx/log」的規格，但值得知道。
- 測試只有 2 個 trivial case，核心流程（REPL 協定、重燒沿用、xlsx 同步）都沒測。
