# UI 專項

方法：對照 `出廠設定工具_介面草圖.html` 與規格 §11，並用 Qt offscreen 模式實際渲染 `MainWindow` 截圖驗證（截圖中文字顯示為方框是 offscreen 環境缺字型的假象，實機 Windows 有微軟正黑體，不是 bug；但**版面與顏色**是真實渲染結果）。

依現行 review 原則，只列會影響使用的問題。

## P1

### A. 四格的狀態顏色完全沒有渲染出來（`ui.py:206`）

`SlotCard` 是 QWidget 子類別，Qt 對子類別**預設不繪製 stylesheet 的 background/border**——需要 `setAttribute(Qt.WA_StyledBackground, True)`。目前 `set_snapshot` 每次都 `setStyleSheet(... border: 3px solid 狀態色 ...)`，但實際畫面上**一條邊框都畫不出來**（截圖已證實：執行中/請確認/失敗的格子全部是白底無框）。

後果：整個 2×2 介面的核心設計——操作員瞄一眼就知道哪格在跑、哪格在等人、哪格失敗——完全失效。狀態只剩右上角的小字。加上目前也沒有草圖裡的大字 PASS／FAIL（規格 v1 明寫「大字 PASS／FAIL 與小卡編號」），PASS 之後畫面幾乎沒有變化。

**修法**：`SlotCard.__init__` 加 `self.setAttribute(Qt.WA_StyledBackground, True)`；並在 PASS/FAIL 狀態顯示大字（草圖的 `.big`：32px+ 粗體置中、用狀態色）。改完請實際打開程式確認邊框顏色會隨狀態變化。

### B. 每片板子的 serial log 沒有寫入 `logs/`（規格 §3）

`logs/` 目錄在整個 `src/` 裡零引用。所有 log 只存在記憶體（`snapshot.logs` → QLabel），**程式一關就全部消失**。FAIL 的板子事後要查原因（燒錄紀錄、開機輸出、Traceback）完全沒有依據——這是產線工具最需要回查的資料。

**修法**：每片開始燒錄時開一個 `logs/<日期時間>_<port>_<MAC或編號>.log`，`_on_log` 與 `_wait_for_boot` 的輸出同步 append，結束時寫入 PASS/FAIL 結果。

## P2

### C. Log 分頁不會捲到最新內容（`ui.py:318-327,415-418`）

Log 用 `QLabel.setText` 放在 `QScrollArea` 裡，新內容進來時捲軸停在頂端——燒錄中切到 Log 分頁永遠看到的是開頭，60 秒開機驗收時看不到即時輸出，等於不能用來「看現在卡在哪」。順帶：每行都重新 join 整串再 setText，log 一長會越來越卡。

**修法**：改用 `QPlainTextEdit`（read-only）+ `appendPlainText`，自動捲動與效能一次解決。

### D. 九格步驟指示列從不更新（`ui.py:104,185-206`）

`steps_label` 是一條靜態文字（連線　韌體　…　LCD），`snapshot.completed_steps` 有在記錄但畫面從未使用——步驟列看起來像進度指示，實際上永遠不變。目前步驟只能靠訊息文字猜。修 A 時可一併把目前步驟上色（done 綠 / now 藍 / 失敗紅，如草圖）。

## 帶過即可（不影響主要操作，coder 有空再處理）

- 開工列沒有顯示「下一號」（草圖有）——操作員無法預先知道下一片會配什麼號。
- 已被其他格選走的 COM port 沒有在下拉裡反灰（草圖有），目前靠按開始時擋。
