## P0 — 新引入的問題

### A. `_enter_raw_repl` 在 friendly REPL 提示字元就提早返回（`provisioning.py:111-117`）

修好 `_read_until` 之後，它現在**只回傳到第一個 marker 為止**——這正是 `_enter_raw_repl` 依賴的舊行為壞掉的地方。

送出 `\x03\x03\x01` 後，板子的輸出順序是：

```
（Ctrl-C 中斷 main.py）... KeyboardInterrupt
>>>                        ← friendly REPL 提示，含有">"！
raw REPL; CTRL-B to exit
>                          ← 這才是我們要的
```

`_read_until(b">", 3)` 會停在 `>>>` 的**第一個 `>`**，此時 buffer 內容不含 `raw REPL` 字樣 → 判定失敗 → 重試 3 次全部一樣 → 觸發無意義的自動重燒 → 重燒完仍然一樣（乾淨韌體按 Ctrl-C 也會先印 `>>>`）→ `_reflash_attempt` guard 擋下 → **每片板子 FAIL**。

舊版（一次讀整包）恰好會把 banner 一起收進來所以能過；第二輪的 fake serial 測試只測了 `execute()`，沒測 `_enter_raw_repl`，所以沒抓到。

**修法**：不要以單一 `>` 當結束符。改成先 `_read_until(b"raw REPL", 3)` 確認 banner 出現，再 `_read_until(b">", 1)` 吃到提示字元；或直接用 `_read_until(b"exit\r\n>", 3)`。**請補一個 fake serial 測試**：輸入 `b">>> raw REPL; CTRL-B to exit\r\n>"`，驗證能成功進入。

## P1

### B. 帳本重複檢查把正常的重燒紀錄當成重複，會鎖死整個工具（`ledger.py:40-59`、`ui.py:376-379`）

CSV 是流水帳：同一片板子重燒（規格明確支援的流程）或 FAIL 後重跑，`append_csv` 都會為**同一個 MAC 再寫一列**（同 MAC、同 token、同小卡編號）。`duplicate_fields()` 只做「值有沒有重複出現」的檢查 → 第一次重燒任何一片板子之後，CSV 必然有兩列同 MAC → `start_slot` 直接跳「帳本資料重複」**拒絕開始任何燒錄**，而且沒有任何方法可以從 UI 恢復。

**修法**：檢查的不該是「值不重複」，而是「對應關係一致」：

- 同一 MAC 的所有列，token 與小卡編號必須相同（不同→真正的資料異常）
- 同一小卡編號不可對應到兩個不同 MAC
- 同一 token 不可對應到兩個不同 MAC

另外 `duplicate_fields()` 只在 CSV 為空時才看 xlsx（`ledger.py:43`）——CSV 有資料時，跨 CSV/xlsx 的重複（例如舊 xlsx 的編號被新 CSV 重用）驗不到，建議合併兩邊資料一起檢查。

### C. DTR/RTS 在開 port 之後才設定，依規格接線會把板子帶進 bootloader（`provisioning.py:51-53`、`ui.py:174-176`）

規格 5.1 明寫「**開 port 前**先設 DTR/RTS 為不作用」。目前是 `serial.Serial(port, ...)` 開啟後才設 `dtr = False`、`rts = False`。pyserial 預設在 open 時 assert DTR 和 RTS，以規格接線（DTR→EN、RTS→IO0）推演：

1. open → DTR、RTS 同時 assert → EN 拉低（板子進 reset）、IO0 拉低
2. `dtr = False` → EN 放開、板子開機——**此時 RTS 還 assert 著，IO0 還是低電位 → 板子進 ROM bootloader，不是 MicroPython**
3. `rts = False` → 太遲了

若燒錄器有 NodeMCU 式雙電晶體電路可以躲過（兩訊號同時 assert 時互相抵銷），但直接接線就會中招——而且症狀會和 P0-A 混在一起難以除錯。`identify()` 同樣有這問題，還外加：對執行中的板子送 Ctrl-C 會把 main.py 停掉，操作員識別完 LCD 就凍住了。

**修法**：建構未開啟的 `Serial()`（不帶 port 參數），先設 `dtr = False`、`rts = False`，再 `.port = ...`、`.open()`——這才符合規格字面要求。若仍需在開啟狀態下操作，釋放順序必須是**先 `rts = False` 再 `dtr = False`**（先放 IO0，再放 EN）。

## P2

### D. 凍結版 esptool 只搜 PATH（`provisioning.py:170-177`）

`shutil.which("esptool.exe")` 只找 PATH。打包後 esptool.exe 通常放在 provision.exe 旁邊，而該目錄不一定在 PATH。應優先嘗試 `Path(sys.executable).parent / "esptool.exe"`，找不到再 fallback 到 `shutil.which`。
